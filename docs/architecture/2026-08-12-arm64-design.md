# Support des images ARM64

## Objectif

Publier Rat King sous la forme d’une image OCI multi-architecture compatible
avec `linux/amd64` et `linux/arm64`, tout en construisant les deux variantes à
chaque push et pull request.

## Architecture CI

Le workflow GitHub Actions conserve ses trois responsabilités :

- `quality` exécute formatage, lint, tests et build du paquet Python ;
- `container` initialise QEMU et Docker Buildx, puis construit les plateformes
  `linux/amd64` et `linux/arm64` sans les publier ;
- `publish`, uniquement pour un tag de version, initialise les mêmes outils et
  publie un unique index OCI multi-architecture sous les tags de version,
  `latest` et `sha-<commit>`.

Les actions officielles utilisées pour QEMU, Buildx et le build sont épinglées
par SHA. La publication continue d’utiliser uniquement le `GITHUB_TOKEN` avec
la permission `packages: write`.

## Image et déploiement

Le Dockerfile reste unique. Sa base Python sur Debian Trixie et les dépendances
Python supportent les deux architectures. Kubernetes continue de référencer un
seul digest : le registre présente un index OCI et le runtime du nœud choisit
automatiquement le manifeste AMD64 ou ARM64 correspondant.

## Vérification

Un test hors réseau contrôle que le workflow déclare exactement les deux
plateformes dans les jobs de validation et de publication. La CI construit
réellement les deux variantes à chaque changement. Après publication, le
manifeste public est inspecté pour confirmer la présence de `linux/amd64` et
`linux/arm64`, puis le digest de l’index est reporté dans le Deployment.

## Livraison

La première release multi-architecture sera `v0.2.3`. Les tags de release déjà
publiés ne seront ni déplacés ni réécrits. Aucune licence n’est ajoutée.
